# Underwrite 개발 계획: 완료된 평가 근거의 소비

기준일: 2026-11-27. 이 문서는 Underwrite의 **제품 개발 정본**이다. 기능 목록을
늘리는 목표가 아니라, 에이전트가 완료된 로컬 평가 파일을 처음부터 올바르게
해석하고 다음 확인에 필요한 자료를 찾는 일을 줄이는 목표를 다룬다. 배포본,
현재 개발 체크아웃, 계획을 아래에서 구분한다. 버전 변경과 공개 배포는
유지관리자가 별도로 결정한다.

## 제품 경계와 가설

Underwrite는 평가를 실행하거나 제안·재시도를 생산하는 도구가 아니다.
완료 파일의 **관측 사실, 원천의 주장, 미확인 상태, 비교 적격성, 다음 검증 과제**를
구조화한 JSON으로 반환하는 소비자 부품이다. 생산자는 원생 실행·trace·export·
검증기를 소유한다. Goppi는 별도 저장소와 배포물을 가진 선택형 동반 앱이며,
Promptfoo·DeepEval·Langfuse도 각각 독립적인 생산자다. Underwrite와
Goppi를 함께 설치해야 하는 일반 의존성은 만들지 않는다.

계약에 대응하는 용어는 다음과 같다. **입장 검사**는 지원 형식·완전한 입력·
검증기 응답을 확인하는 일이고, **증거 계보**는 선택한 원본 바이트와 그
파일에서 나온 결과를 연결하는 일이다. **비교 적격성**은 사례·단계·반복·
모집단·지표 정의가 해당 비교 질문에 맞는지 판단하는 일이다. **판정 유보**는
필요한 근거가 없을 때 결론 대신 이유와 다음 과제를 반환하는 일이다.
해시는 바이트 동일성이지 출처 인증이 아니며, 생산자 판정은 독립 정답이
아니다. `not_measured`, `indeterminate`, `abstained`, `not_run`을 성공이나
서로 같은 결측으로 바꾸지 않는다. 사람이 승인·반려할 권한도 생성하지 않는다.
구현 owner와 계층은 [기여 가이드](../../CONTRIBUTING.md#implementation-owners)를 따른다.

유지관리자 결정(2026-11-27): 자체 구현 비용이 내려간 환경에서는 기능 수나
어댑터 수 자체를 효용으로 세지 않는다. 제품 가설은 **같은 완료 파일에 대한
최초 올바른 해석까지의 시간이 줄고, 잘못된 승인·반려가 늘지 않으며,
이종 생산자 어댑터의 유지보수 총비용이 감당 가능하다**는 것이다. 아직
실사용 효과는 측정되지 않았다. 비교 실험과 중단 기준을 먼저 고정한 뒤
검증한다.

## 확인된 현재 상태

| 범위 | 확인된 사실 | 해석 한계 |
| --- | --- | --- |
| **배포본** | 공개 설치 안내의 `underwrite==0.2.0`은 완료된 지원 파일을 감사하며, Goppi paired+trajectory 입력에 `goppi_trajectory_review.v1`을 반환한다. [README](../../README.md#installed-package--020)와 [사용 안내](../../AGENT_USAGE.md)를 따른다. | 개발 체크아웃의 v3·v4 계약을 배포본의 기능으로 적지 않는다. 선택한 실행 파일의 `capabilities --json`을 확인한다. |
| **현재 개발 체크아웃** | 공개 `main`의 [소비 안내](../../AGENT_USAGE.md)는 Goppi `execution.v2` / `row.v2` / trajectory document.v2를 별도 입력 계열로 수용한다. 이 계열은 review·outcome-actions·record/read v4, 기존 v1 입력은 v3를 사용한다. 혼합 계열과 맞지 않는 검증기 응답은 거부한다. [공개 합성 적합성 파일](../../fixtures/conformance/goppi-execution-v2/README.md)과 이전 계열 회귀가 있다. | 입력의 build·split 선언은 생산자 주장이다. 검증기 응답과 선택 바이트를 대조해도 실행 파일 신원, 독립 출처, 원생 평가의 정답은 증명하지 못한다. |
| **로컬 설치 쌍** | [설치 쌍 검사](../../CONTRIBUTING.md#producer-compatibility)는 특정 Goppi tarball과 Underwrite/core wheel을 임시 설치해 네이티브 정상·거부 경로, 패키지 바이트, 계약을 검사한다. 해당 검사 및 `execution.v2` 소비는 수용된 구현이다. | 공개 Goppi npm `0.0.1`의 paired-export 지원이나 일반 사용 가능성을 뜻하지 않는다. 합성 fixture의 build digest는 설치된 tarball digest와 별개다. 설치 쌍 결과는 그 고정 산출물의 호환성 증거다. |
| **효용과 비교 주장** | 단일 파일 감사, `review-artifacts`, `compare-results`, 읽기 전용 에이전트 표면 등은 개발 체크아웃에서 사용 가능하다. 이전 합성·소규모 관측은 결함을 찾는 자료로 남아 있다. | 사람의 최초 올바른 해석 시간, 잘못된 승인·반려 감소, 이종 생산자 총비용의 개선은 미측정이다. 공개 합성 자료만으로 동일 과제·동등 지표·인과적 개선을 선언하지 않는다. |

고정 입력을 현재 소비 계약으로 다시 판정하는 작업은 **대기 중**이다.
유지관리자가 접근 통제된 로컬 실행 명세에 입력 바이트 해시, 설치 산출물의
해시, 명령, 기대·금지 주장과 독립 판정 기준을 동결하기 전에는 시작하지
않는다. 이번 문서 개정은 새 점수, 원생 실행의 성공, 실사용 효과를 보고하지
않는다. 결과가 확인되면 공개 가능한 계약·한계만 위 상태에 반영한다.
공개 저장소에는 기존 공개 합성 fixture를 유지하고 비공개 원본 또는 추가
검사용 fixture를 넣지 않는다.

## 실행 순서와 입장 조건

| 순서 | 좁은 결과와 의존관계 | 통과 증거 | 정지 조건 |
| --- | --- | --- | --- |
| **1. 고정 실행 재채점** | 위 로컬 명세가 동결된 뒤 완료된 평가 파일과 선택한 설치 쌍을 현재 소비 계약으로 다시 읽는다. | `execution.v2` 정상·거부, 기존 계열 회귀, 결과의 모집단·결측·다음 과제를 실제 CLI/API에서 대조한다. 독립 확인 불가 항목은 그대로 미확인으로 기록한다. | 동결 명세·검증기가 없거나 소비자가 생산자 주장을 독립 사실로 승격하면 시작 또는 진행을 멈춘다. |
| **2. 최초 해석 파일럿** | 1의 지원 범위가 확정되면 실제 완료 파일의 같은 질문을 현행 JSON, 직접 원본 링크, 필요한 최소 안내로 비교한다. 과제·정답·순서·권한을 먼저 고정한다. | 검토 세션별 최초 올바른 해석까지의 사람 활동시간과 전체 경과시간을 분리하고, 잘못된 승인·반려, 불필요한 보류, 원본 재확인, 에이전트 호출 수를 기록한다. 독립 판정자가 원본과 답을 확인한다. | 아래 판정선을 못 채우면 기본 출력이나 새 표면으로 승격하지 않는다. 합성 파일만 있으면 효용 주장을 보류한다. |
| **3. 이종 비교 입장 검사** | 1·2에서 실제 비교 질문이 남고, 서로 다른 생산자의 **같은 과제** 완료 파일·공통 사례 명부·입출력·조건·지표 정의를 확보한 뒤 진행한다. | 사례·단계·반복과 정책 identity를 묶고, 비교 가능/불가 이유 및 필요한 원본을 반환한다. 다른 지표나 계획 모집단 부재는 명시한다. | ID·순서·점수·해시만 같거나 생산자별 의미가 다르면 동등성·개선 계산을 보류한다. 원생 관계가 빠졌다면 생산자에게 필요한 export 근거를 요청한다. |
| **4. 최소 구현 또는 종료** | 1–3에서 재현된 소비자 결함이나 반복 마찰이 있을 때만 기존 의미 owner를 고친다. | 변경 전후 같은 과제의 정확성·시간·복구 비용과 어댑터 유지 비용을 비교하고, 계약 회귀·독립 검토·[preflight](../../.codex/skills/underwrite-preflight/SKILL.md)를 통과한다. | 아래 판정선에서 유지 비용을 상쇄하지 못하면 기능 추가를 종료한다. 생산자의 실행·제안 책임을 Underwrite로 옮기지 않는다. |

### 파일럿 판정선

파일럿 전에 실제 완료 파일과 판단 질문을 고정하고, 서로 다른 원본을 같은
난도의 질문에 배정한다. 단위는 행이나 반복이 아니라 **독립 검토 세션**이다.
같은 검토자의 반복 학습이 한 조건에만 쏠리지 않게 조건 순서를 교차한다.
최소 10세션씩 현행 JSON·직접 링크·안내 조건을 관찰하기 전에는 제품 효용
결론을 내리지 않는다. 관측 창은 첫 세션부터 30일이며, 목표 세션을 못 모으면
`미측정`으로 닫고 기간을 임의로 늘려 성공을 만들지 않는다.

| 지표 | 단위·기준선 | 승격 조건과 중단 규칙 |
| --- | --- | --- |
| 최초 올바른 해석 | 과제 제시부터 독립 판정자가 사실·미확인·비교 적격성·다음 과제를 모두 맞다고 확인한 최초 답까지의 사람 활동분. 현행 JSON과 직접 링크 각각의 중앙값을 기준으로 한다. | 안내 조건의 완료율이 두 기준선보다 낮지 않고, 완료 세션의 중앙값이 **두 기준선 모두보다 20% 이상 짧아야** 한다. 틀린 답은 완료 시간으로 세지 않고 관측 창 끝까지 미완료로 둔다. 어느 조건이든 완료 세션이 절반 미만이면 시간 우위를 주장하지 않는다. |
| 잘못된 승인·반려 | 독립 판정자가 사전 고정한 결론과 다른 승인·반려의 세션 수와 비율. 두 기준선과 부정 사례를 함께 기록한다. | 안내 조건의 잘못된 승인은 **0건**, 잘못된 반려는 **어느 기준선보다도 많지 않아야** 한다. 하나라도 어기면 확장을 멈추고 원인과 원본을 검토한다. 작은 표본의 0건을 일반 안전성 증명으로 부르지 않는다. |
| 어댑터 유지보수 총비용 | 형식별 변경 사건당 개발·검토·회귀·설치 쌍 검사·지원 복구의 사람 시간과 30일 누계. 실제 지원 형식·사건 수를 분모로 두고, 관측하지 않은 사건은 0비용으로 세지 않는다. | 새 어댑터·출력의 예상 12개월 유지 시간에 관측된 사용량을 적용한 검토 시간 절감보다 비용이 크거나 사용량을 모르면 승격을 보류한다. 추정 근거와 실제 시간을 분리하고 다음 변경 사건에서 다시 계산한다. |

유지보수 총비용은 어댑터별 초기 구현시간만이 아니라 형식 변경 감지,
fixture·계약 갱신, 설치 쌍 재검사, 회귀 수리, 리뷰와 사용자 복구 시간을
포함해 기록한다. 분모는 실제 지원 형식과 변경 사건이며, 계약별 비용을
분리한다. 같은 원천을 재포장한 여러 행이나 모델의 동의는 독립 표본이
아니다. 새 결과 계약은 측정된 오판 또는 반복 마찰을 해결하는 최소 필드가
있을 때만 고려한다. 읽기 전용 stdio 표면과 구조 개선은 각각
[에이전트 표면 계획](AGENT_SURFACE_PROGRAM.ko.md),
[구조 계획](STRUCTURE_PROGRAM.ko.md)의 owner를 따른다.
