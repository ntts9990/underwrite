# Underwrite 기능 개선 마일스톤

기준일: 2026-10-28. 이 문서는 기존 M1–M3 결과를 다시 완료로 선언하거나
패키지 버전을 올리는 계획이 아니다. 제품의 목적은 **완료된 로컬 평가 산출물에서
실제로 확인되는 사실, 아직 모르는 사실, 다음 검증에 필요한 자료를 에이전트가
바로 구분하도록 하는 것**이다. 생산자 실행·trace 수집·재시도·후보 제안은
Goppi와 각 평가 도구의 책임으로 둔다. Underwrite는 그 결과의 의미와
비교 가능성만 다룬다.

## 현재 기준선과 중단 경계

- Promptfoo 기본 감사(`promptfoo_accounting.v2`)는 선언 집계와 제공된 행의
  불일치를 찾지만, 성공한 JSON 응답에 구조화된 확인 과제가 없다. 합성
  `synthetic-promptfoo-count-mismatch.json`에서 재현된다. README의 다음 확인
  문단을 찾아야 하는 수동 단계가 생긴다. 이것은 사람 시간 절감의 증거가 아니다.
- DeepEval/Langfuse 감사와 Goppi 궤적·교차 산출물 검토에는 이미 후속 행동이
  있다. 새 범용 작업 엔진을 만들 이유는 없다.
- M3a의 `review-artifacts`는 선택한 Goppi C55·Promptfoo 산출물의 선언된 사례
  대응과 미비한 근거를 기술한다. 전체 M3의 적격 원본 근거와 보호된 PR 검사는
  아직 확보되지 않았다. 수용되지 않은 Goppi 변경·해시 일치를 독립 검증으로
  취급하지 않는다.

| 순서 | 사용자가 얻을 결과 | 구현 경계와 완료 증거 | 확대/중단 조건 |
| --- | --- | --- | --- |
| **F1. 단일 산출물의 다음 검증 과제** | 에이전트가 Promptfoo 불일치 JSON 한 번으로 무엇을 원본에서 확인할지 안다. | 기존 v2 기본 출력·record는 그대로 두고, 명시적 `--view actions`의 엄격한 새 계약에 불일치 종류별 과제를 추가한다. 순수 계수 결과에서만 파생하며 원인·누락 실행·승인 권한을 추정하지 않는다. 일치·집계 불일치·행 플래그 충돌·비공개 내용·오류 경로를 실제 CLI와 Python API로 검증한다. | 기존 v2 소비자를 깨거나 원본에 없는 사실을 보충하면 중단·수정한다. 실제 사용자 이득은 별도 측정 전까지 미측정. |
| **F2. 완료된 산출물의 검토 파일럿** | 사용자가 결과와 근거를 더 적은 탐색으로 올바르게 해석하는지 확인한다. | `OUTCOME_EVIDENCE_DELEGATION_METHOD.ko.md`에 따라 실제 완료 파일과 판단 질문을 고정한 뒤 현재 출력/직접 링크/파생 안내를 동일 권한·입력에서 비교한다. 정확성, 잘못된 승인·반려, 사람 활동시간, 에이전트 단계와 원본 확인을 분리해 기록한다. | 링크만으로 충분하거나 안내가 오판을 늘리면 기본 출력 승격을 하지 않는다. 합성 fixture로 효능을 주장하지 않는다. |
| **F3. 생산자 간 비교 가능성 확대** | 실제로 대응되는 사례·단계·반복만 묶이고 비교 불가 이유가 남는다. | M3a의 선택 바이트·선언 대응·`next_verification_tasks`를 재사용한다. 수용된 생산자 원본/fixture에서 없던 관계가 확인될 때만 계약과 어댑터를 확장한다. | 이름·순서·단일 점수만으로 동일 사례나 인과관계를 만들면 중단한다. Goppi 쪽 export는 읽기 전용으로 확인한다. |
| **F4. 검증 가능한 행동·판정 경계** | 후속 에이전트가 어떤 자료를 받아야 판단을 계속할 수 있는지 안다. | Goppi의 수용된 사전 권한·행동·검증기 근거가 있을 때만 기존 관계 결과에 연결한다. `not_measured`·`indeterminate`·`abstained`를 분리하고 사람의 채택 권한을 유지한다. | 원생 관계가 없다면 과제만 반환한다. 범용 원인/개선 추천기나 자동 승인으로 넓히지 않는다. |

각 단계는 결과·실패 반례를 먼저 정하고 구현 → 실제 진입점 검증 → 별도
리팩토링·적대적 리뷰 → 저장소 preflight를 거친다. 필요한 후속 결함은 같은
단계에서 해결한다. 패키지 버전 변경, provider 실행, 공개·배포는 이 계획에
포함되지 않는다.
