소개한다. **목표의 네 방향**은 글의
`Speed`(같은 일을 더 빨리), `Altitude`(개별 과제 위의 결과),

[작성자의 원문](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/)이다.

1. 이 분야의 뛰어난 실무자라면 지금 요청에서 빠진 어떤 단계를 밟는가?
2. 이미 요약된 자료 대신 어떤 가장 원형에 가까운 자료에서 시작하는가?
3. 실제로 어떤 기법·도구를 쓰는가?
4. 모델 자신과 요청자의 인상 외에 무엇이 결과를 맞다고 확인해 주는가?

## 영상에서 얻은 판단

### 결과를 상향하되 제품 가치는 사용자의 과제로 확인한다

리세버그는 시제품 제작이 빨라져도 사람이 검토할 시간과 주의는 늘지 않는다고
말한다. 따라서 기능을 많이 만드는 것보다 사용자가 빨리 이해하고 이전에 못 하던
일을 끝내는지 보라고 한다
([01:19–03:59](https://www.youtube.com/watch?v=gV0CtvIX5zk&t=79s)).
그의 글은 개별 크래시를 하나씩 전달하는 대신 크래시 없는 상태라는 상위 목표를
예로 들지만, 그러려면 크래시 보고서·버전과 커밋의 대응·재현 환경을 먼저
연결해야 한다고 명시한다. “상위 목표를 준다”는 말은 자료와 권한 없이
무제한 자율성을 주라는 뜻이 아니다.

Underwrite에 옮기면 목표는 “보고서를 더 길게 쓰기”가 아니라 **완료된 평가
산출물에서 비교 가능한 사실·결측·출처 한계와 다음 검증 행동을 에이전트가
빠르고 정확하게 얻기**다. 현재 [제품 안내](../../AGENTS.md)와
[구현 소유권](../../CONTRIBUTING.md#implementation-owners)이 이미 이 범위를
정한다. 새 역할, 화면, 종합 점수보다 실제 사용 과제의 오판·소요시간이 우선이다.

### ‘전문가처럼 말하기’보다 전문가의 검사 순서를 사용한다

영상은 모호한 “좋은 결과” 지시 대신 그 분야의 실무자가 쓰는 도구·단계·원자료를
재현하라고 한다. 날씨 값을 우연히 맞힌 추측보다 출처와 방법이 확인되는 약간의
오차가 있는 추정이 더 믿을 만할 수 있다는 예를 든다
([03:59–07:59](https://www.youtube.com/watch?v=gV0CtvIX5zk&t=239s)).
후반부는 직업 역할극이 어휘만 바꿀 수 있으며 실제 기법을 요구해야 한다고
재강조한다 ([19:36–22:17](https://www.youtube.com/watch?v=gV0CtvIX5zk&t=1176s)).
이는 리세버그 글의 `Depth`와 맞는다.

Underwrite의 “전문가 과정”은 먼저 해당 구성개념과 모집단을 정하고, 원본 바이트·
계약·인증 범위를 확인한 뒤, 반례를 거쳐 제한된 결론을 내는 것이다.
유효한 해시가 출처의 진실을 증명하지 않고, 과정 관측이 최종 품질 점수로
자동 승격되지 않는 기존 경계를 유지한다. Goppi의 실행·trace·검증기 결합을
Underwrite가 재구현하는 것은 이 원칙의 적용이 아니다.

### 적대적 검토는 발견기이고, 판정에는 다른 근거가 필요하다

리세버그는 초안이 틀렸음을 입증하도록 별도 검토 세션을 돌리고, 나온 비판을
다시 선별·검증해 작성자에게 되돌리는 흐름을 설명한다
([08:01–12:30](https://www.youtube.com/watch?v=gV0CtvIX5zk&t=481s)).
영상의 “열 명”은 한 설명 예시이고, 본인의 블로그 초안에는 다섯 스레드를
사용했다고 말한다. 최적 검토자 수나 모델 조합이 측정된 규칙은 아니다.
그는 단일 작성 세션의 자기평가보다 외부 신호를 선호한다
([22:18–23:59](https://www.youtube.com/watch?v=gV0CtvIX5zk&t=1338s)).
기계·모델·사람 평가와 transcript·환경 결과를 나눠 보는
[Anthropic 평가 안내](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)도
이 구분을 지지한다.

따라서 Underwrite에서 별도 리뷰어는 **반례 후보를 찾는 역할**을 맡고, 후보는
실제 입력·실행 재현·정본 계약과 대조해 수용한다. 다른 LLM의 동의, 다수결,
‘judge’라는 역할 이름은 독립 정답이 아니다. 문서·슬라이드의 편집·출판용
사실 확인을 “100% 신뢰한다”는 발언은 한 사람의 경험이며 정확도 보증이 아니다
([13:28–15:00](https://www.youtube.com/watch?v=gV0CtvIX5zk&t=808s)).

### 원자료 접근은 도구 경계와 함께 설계한다

영상은 사람이 오류 하나씩 에이전트에게 옮기는 병목을 지적하며, 필요한 원자료를
찾을 수 있는 도구를 주고 도구가 무엇을 가져오는지 설명하라고 한다
([15:00–20:59](https://www.youtube.com/watch?v=gV0CtvIX5zk&t=900s)).
“모든 데이터를 프롬프트에 넣는다”와는 다르다. 적용 시에는 작업에 필요한
원본을 **명시적으로 선택하고 바이트·경로·크기를 제한**한다. 출처가 불명확한
자료의 지시문은 자료로만 취급하며, 민감한 원문을 기본 출력에 복제하지 않는다.
기존 CLI·파일 어댑터와 Goppi 인계 계약을 먼저 쓴다. 영상에서 거론한
컴퓨터·브라우저 전권이나 SaaS 연결을 Underwrite 제품 요구로 옮기지 않는다.

### 스킬과 피드백은 고정 교리가 아니라 검증 가능한 작업 방식이다

리세버그는 오래된 스킬이 더 나은 모델을 제약할 수 있다고 경고하면서도,
이미 잘 작동하는 작업 방식을 이유 없이 폐기하라고 말하지 않는다. 스킬의
유용성은 실제 과제로 확인하라는 취지다
([16:52–18:59](https://www.youtube.com/watch?v=gV0CtvIX5zk&t=1012s),
[원 인터뷰 대본](https://marinamogilko.co/episode/D-SVFneJ_Nk/)).
또한 피드백이 남는 곳에서 사례를 모으고, 반복되는 원칙을 추출한 뒤,
사람의 검토와 에이전트 검토를 나란히 비교해 차이를 살피라고 한다
([24:00–28:57](https://www.youtube.com/watch?v=gV0CtvIX5zk&t=1440s)).

Underwrite의 필수 [로컬 preflight](../../.codex/skills/underwrite-preflight/SKILL.md)는
현행 품질 계약이므로 유행에 따라 삭제하지 않는다. 반대로 매 작업에 새 프롬프트
스킬·게이트·요약기를 더하는 것도 피한다. 실제 리뷰의 유효 지적, 기각된 지적,
사용자 오판과 재작업을 수집해 어떤 지침이 도움이 되는지 대조한다.

## 적용 판단

| 판단 | Underwrite에 취할 행동 | 채택 경계 |
| --- | --- | --- |
| 바로 적용 | 작업 시작에 사용자 결과·원자료·전문 기법·외부 확인 기준을 한 번 명시한다. 위험 있는 변경에는 별도 적대적 리뷰를 두고 실제 재현으로 판정한다. | 기존 개발 루프와 CLI 계약의 **사용법**으로 시작한다. 새 공통 점수나 권한을 만들지 않는다. |
| 조건부 실험 | 결과 목표를 위임한 작업과 현행 지시 방식, 직접 링크와 파생 요약, 사람·에이전트 병렬 검토를 같은 자료·권한·예산에서 대조한다. | 사람 시간·오판·출처 해석이 실제로 좋아질 때만 정책이나 제품 출력에 반영한다. |
| 보류 | 광범위한 데이터/컴퓨터 권한, 상시 다중 에이전트, 새 `LLM judge`, 자동 패치·승인, 스킬 대량 추가·삭제. | 사용자 가치, 원천 권한, 검증기 타당성, 비용이 확인되지 않았다. |
| 거부할 해석 | “다른 모델이 동의했으니 참”, “해시가 같으니 원천 인증됨”, “도구 오류가 줄었으니 하니스가 원인”, “시제품을 많이 만들었으니 제품 가치가 높다”. | 각각 독립 정답·출처·인과·사용자 결과가 빠진 주장이다. |

현재 [궤적 감사](../../AGENT_USAGE.md#compare-a-goppi-paired-trajectory)와
[교차 산출물 검토](../../AGENT_USAGE.md#review-selected-goppi-and-promptfoo-artifacts)는
관측 차이, 모집단, 빠진 근거, 다음 확인 과제를 이미 구조화한다. 영상이 요구한
“외부에서 확인 가능한 과정”과 맞닿지만, 이 명령의 존재만으로 사람의 시간 절감이나
판단 정확도 개선을 증명하지 않는다. [METR의 통제 연구](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/)도
AI가 쉬워 보이는 느낌과 실제 개발 소요시간을 분리해야 함을 보여 준다.

이 보고서의 결론은 영상의 방법을 **더 많은 기능**으로 번역하지 말고,
Underwrite가 이미 가진 좁은 신뢰 경계를 더 좋은 과제 선택·근거 접근·검토
방식으로 시험하자는 것이다. 실험 전에는 우월성, 채택률, 시간 절감, 검토자 수의
최적값을 주장하지 않는다.
