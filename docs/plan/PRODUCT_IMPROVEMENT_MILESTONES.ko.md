# Underwrite 기능 개선 마일스톤

기준일: 2026-10-28. 이 문서는 기존 M1–M3 결과를 다시 완료로 선언하거나
패키지 버전을 올리는 계획이 아니다. 제품의 목적은 **완료된 로컬 평가 산출물에서
실제로 확인되는 사실, 아직 모르는 사실, 다음 검증에 필요한 자료를 에이전트가
바로 구분하도록 하는 것**이다. 생산자 실행·trace 수집·재시도·후보 제안은
Goppi와 각 평가 도구의 책임으로 둔다. Underwrite는 그 결과의 의미와
비교 가능성만 다룬다.

## 현재 기준선과 중단 경계

- Promptfoo 기본 감사(`promptfoo_accounting.v2`)는 선언 집계와 제공된 행의
  불일치를 찾지만, 성공한 JSON 응답에 구조화된 확인 과제가 없다. 합성
  `synthetic-promptfoo-count-mismatch.json`에서 재현된다. README의 다음 확인
  문단을 찾아야 하는 수동 단계가 생긴다. 이것은 사람 시간 절감의 증거가 아니다.
- DeepEval/Langfuse 감사와 Goppi 궤적·교차 산출물 검토에는 이미 후속 행동이
  있다. 새 범용 작업 엔진을 만들 이유는 없다.
- M3a의 `review-artifacts`는 선택한 Goppi C55·Promptfoo 산출물의 선언된 사례
  대응과 미비한 근거를 기술한다. 전체 M3의 적격 원본 근거와 보호된 PR 검사는
  아직 확보되지 않았다. 수용되지 않은 Goppi 변경·해시 일치를 독립 검증으로
  취급하지 않는다.

| **F4. 검증 가능한 행동·판정 경계** | 후속 에이전트가 어떤 자료를 받아야 판단을 계속할 수 있는지 안다. | Goppi의 수용된 사전 권한·행동·검증기 근거가 있을 때만 기존 관계 결과에 연결한다. `not_measured`·`indeterminate`·`abstained`를 분리하고 사람의 채택 권한을 유지한다. | 원생 관계가 없다면 과제만 반환한다. 범용 원인/개선 추천기나 자동 승인으로 넓히지 않는다. |

## 진행 상태

- **F1 구현·로컬 검증 완료:** `fe3b31f`에서 Promptfoo 행동 뷰를 추가하고
  기본 v2와 기록 경로를 보존했다. 전체 로컬 preflight와 별도 리뷰가 통과했다.
  이는 배포나 실사용 효능의 증거가 아니다.
- **F2의 에이전트 경로 연결:** `underwrite-review` 스킬이 설치 CLI의
  capability를 확인하고, 다음 확인 질문에는 행동 뷰를, C55와 Promptfoo의
  지원되는 완료 파일 세 개에는 기존 `review-artifacts`를 선택하도록 한다.
  Promptfoo 집계 불일치나 필수 사례 메타데이터 부재가 있으면 결합을 거부한
  상태로 남기고, 가능한 단일 소스 감사와 원본 확인 과제로 돌아간다.
  지원하지 않는 설치본에서도 단일 소스 감사만 사용하며 사례 대응을
  만들어내지 않는다.
  이 연결은 파일럿 준비이지 사람의 시간·오판율을 측정한 결과가 아니다.
- **F3·F4 조건 미충족:** 현재 확인한 Goppi `main`의 공개 휴대형 궤적은
  호출 부모·재시도·결과 소비 관계를 보존하지 않는다. 기존 사실만으로
  인과관계나 동일 지표를 새로 선언하지 않는다.

### F2a 완료: 일반 export의 교차 검토 준비 상태

실제 Promptfoo 0.124.1 완료 export는 단독 계수가 일치하지만
`testCase.metadata.case_id`와 `slot_kind`가 없어 C55와의 엄격한
`review-artifacts`에서 거부된다. F2a는 세 파일을 한 번씩 검토하여 정확한
바이트 식별자·Goppi 선택 필드 결속·Promptfoo 계수와 **부족한 소유자 선언**을
한 JSON에 반환하는 명시적 `--view readiness`다. 기존 기본
`cross_artifact_review.v1`과 owner correspondence 검증은 그대로 둔다.
역할이 없는 행의 subject/control 수는 `null`이고, 메타데이터가 다 있어도
subject 행이 없으면 실제 subject 입력을 요구한다. 비교 가능한 사례·동등
지표·개선·승인은 만들지 않는다. 이 결과는 F2의
실사용 시간·오판율 파일럿을 대신하지 않는다.

완료 기준은 실제 공개 fixture와 혼합·부분 메타데이터, 변경된 C55 해시,
Promptfoo 집계 불일치, 지원하지 않는 세대, private canary, 잘못된 선언을
CLI·Python API·설치 wheel에서 확인하고, 별도 리팩토링·독립 리뷰·정본
preflight를 통과하는 것이다. 다음 단계는 F2 사용자 과제의 실제 관측이며,
그 전에는 안내 뷰가 시간이나 정확도를 개선했다고 주장하지 않는다.

### F2b 완료: 선택한 원본과 검토 결과의 동일 바이트 보관

보관된 C59 검토에서는 에이전트가 원본 3개, 소유자 대응 선언과 결과의 경로를
손으로 적은 다섯 파일 `record_spec.v1`을 만들고 다시 읽어 저장했다. 당시
기록의 해시는 일치했으므로 실제 손상 사례가 아니다. 그러나 검토와 저장
사이 원본 경로를 다시 여는 작업과 저장 명세 작성은 사용자 단계이고,
일반 `records save`는 결과가 주장하는 원본 해시와 저장한 원본의 관계를
자동 확인하지 않는다.

첫 범위는 **명시적으로 요청된 엄격한 owner-mapped 검토**만 `records
review-artifacts` 한 번으로 수행하는 것이다. 이미 읽어 검토한 원본 3개와
대응 선언의 정확한 바이트, 생성된 검토 결과 또는 유한 진단, 경로 없는
호출 기록을 기존 불변 저장소에 보관하고 즉시 검증한다. 일반
`review-artifacts`의 출력과 no-map/readiness 경로는 바꾸지 않는다.
입력 수집 실패·설치 계약 오류·출력 상한 오류는 저장 전에 거부한다. 완전한
입력의 분석 실패와 저장 실패는 분리하고, 저장소의 무결성을 생산자 출처
인증이나 비교·채택 권한으로 승격하지 않는다. 동일 바이트 재조회·원본 경로
변경·기존 ID 충돌·사유 있는 실패·비밀 비노출·설치 wheel을 통과해야 한다.
이 기능 역시 F2 실사용 시간 절감의 측정 결과가 아니다.

2026-10-29 공개 합성 파일을 사용한 로컬 첫 사용 탐색에서, 충분한
`review-artifacts` 결과 뒤에 불필요한 `inspect-result` 호출이 관찰됐다.
스킬은 이 중복 호출을 제한하도록 수정했다. 수정 후 같은 과제의 로컬
재시험에서는 준비 상태 결과 한 번으로 답했다. 원시 상호작용 로그를 추적
보관하지 않은 일회성 관찰이므로 재현 가능한 제품 실험이나 F2의 효과
근거로 세지 않는다. 사람 시간·오판율·일반적인 에이전트 효율은 여전히 미측정이다.

후속 실행 검토에서 엄격한 no-map 경로가 Promptfoo subject 행이 0개이거나
C55와 같은 사례 ID가 하나도 없는데도 작성 불가능한 대응표를 요구하는
결함을 재현했다. 두 보기의 첫 소유자 과제를 같은 순수 선행조건 계산에
맞춰 각각 subject 행 또는 맞는 원천 사례 ID를 요청한다. ID 일치는 선언
가능성만 뜻하며 동일 과제·지표나 개선을 증명하지 않는다.

2026-10-30 실제 Promptfoo CLI가 로컬 결정적 provider로 만든 7행 완료
export를 두 에이전트가 문서/스킬 출발 경로에서 각각 검토했다. 둘 다 집계
3/1/3의 일치와 계획 모집단·개선·채택 권한의 미확인을 올바르게 구분했고,
원본 JSON을 직접 다시 읽지 않았다. 명령·종료·출력은 비공개 로컬 기록에
남겼다. 합성 과제의 에이전트 두 명으로 사람의 시간·오판율이나 경로 간
속도 차이를 측정했다고 주장하지 않는다. 같은 F2a 선행조건의 subject 부재와
사례 ID 불일치는 설치 wheel CLI smoke에서도 검사한다. 다음 F2 판단은
승인된 공개 자료와 독립 실제 사용자 과제로 진행한다.

같은 날 공개된 원본 그대로의 DeepEval 4.2.8 trace TestRun에 대한 스킬 출발
에이전트 1회 점검에서는 metric 집계와 별도 trace-index가 같은 `raw_hash`를
가리켰다. 도구 오류 1건과 성공 1건, 원천의 사례 성공 주장을 재시도 효과나
에이전트 개선으로 승격하지 않았고, 필요한 원본 맥락을 찾았다. 이 역시
사람 효과나 생산자 진실성의 근거가 아니다. 이 과정에서 오래된 fixture
안내가 현재 개발본의 trace 포함 metric 집계를 여전히 거부한다고 적은
문서 오류를 발견해, 공개 0.2.0과 개발본의 실제 동작을 구분해 바로잡았다.

각 단계는 결과·실패 반례를 먼저 정하고 구현 → 실제 진입점 검증 → 별도
리팩토링·적대적 리뷰 → 저장소 preflight를 거친다. 필요한 후속 결함은 같은
단계에서 해결한다. 패키지 버전 변경, provider 실행, 공개·배포는 이 계획에
포함되지 않는다.
